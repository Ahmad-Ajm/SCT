# SCT — دليل المستخدم

**SCT (أداة الزحف البسيطة)** زاحف ومدقّق SEO يعمل محلياً على جهازك. يزحف الموقع، ويستخرج
بيانات SEO داخل الصفحات، ويشغّل محلّلات تقنية، ويدمج اختيارياً بيانات Google Search Console
و Google Analytics 4، ثم يُنتج تقارير قابلة للتنزيل (HTML/PDF/Excel/CSV/JSON) — كل ذلك على
جهازك. لا تغادر أي بيانات حاسوبك إلا إذا فعّلت تكاملاً صراحةً.

هذا الدليل عملي وموجّه للمهام. للتفاصيل المعمارية والداخلية راجع
`docs/ARCHITECTURE_AR.md` (أو `docs/ARCHITECTURE.md` بالإنجليزية). لأعلام سطر الأوامر
راجع `docs/CLI_AR.md`. للمساهمة أو توسعة الأداة راجع `CONTRIBUTING_AR.md`.

---

## 1. التثبيت

يتطلّب **Python 3.10 أو أحدث**.

```bash
# من جذر المشروع
python -m pip install -r requirements.txt

# مطلوب فقط لتقارير PDF وتصيير JavaScript:
playwright install chromium
```

ملاحظات:
- الواجهة المرئية تحتاج `fastapi` و`uvicorn` و`jinja2` و`python-multipart` (مضمّنة في
  `requirements.txt`).
- تكامل GA4 يحتاج إضافياً `google-analytics-data` (معلّق في الملف — ثبّته فقط إن استخدمت GA4).
- مستشار الذكاء الاصطناعي **لا يحتاج أي مكتبات إضافية** (يستخدم `requests`).
- **التثبيت التلقائي للمتطلبات:** عند حاجة الأداة لمكتبة اختيارية غير مثبّتة (مثل `openpyxl`
  للإكسل أو `playwright` أو مكتبات Google) تُثبّتها **تلقائياً مع إعلامك** ودون طلب موافقة،
  محصورةً في قائمة مكتبات الأداة المعروفة فقط (لا حزم عشوائية). لتعطيل ذلك والتثبيت يدوياً
  ضع متغيّر البيئة `SCT_NO_AUTO_INSTALL=1`.

## 2. البدء السريع

### الخيار أ — الواجهة المرئية (مُوصى به)

```bash
python webapp/run.py
# ثم افتح http://127.0.0.1:8000
```

أدخِل رابطاً، اضغط **ابدأ**، وتابع التقدّم الحيّ. عند الانتهاء تظهر أزرار التنزيل
(HTML, PDF, Excel, JSON, CSV, XML) إضافةً إلى **استكشاف النتائج**.

لإتاحتها على الشبكة المحلية: `python webapp/run.py --host 0.0.0.0 --port 9000`.

### الخيار ج — Docker (أمر واحد، يتضمّن Chromium)

```bash
docker compose up --build
# ثم افتح http://127.0.0.1:8000
```

مبنية على صورة Playwright الرسمية، فيعمل تصيير JS وتقارير PDF مباشرةً. تُحفظ المخرجات في
`./webapp_jobs`، والأسرار تُقرأ من `.env` وقت التشغيل (لا تُخبز في الصورة).

### الخيار ب — سطر الأوامر

```bash
python main.py --url https://example.com --mode audit
```

خيارات مفيدة:

| الخيار | المعنى |
|--------|--------|
| `--url <url>` | تجاوز رابط البداية من `config.yaml` |
| `--mode audit\|competitor\|compare` | وضع الزحف (الافتراضي `audit`) |
| `--config <path>` | استخدام ملف إعداد مختلف (الافتراضي `config.yaml`) |
| `--sync` | استخدام الزاحف المتزامن (أبطأ؛ للتشخيص) |
| `--analyze-only` | تخطّي الزحف وإعادة تحليل قاعدة بيانات موجودة |
| `--no-resume` | بدء جديد (تجاهل التقدّم المحفوظ) |
| `--skip-external` | تخطّي فحص الروابط الخارجية (أسرع) |
| `--clear-cache` | مسح كاش الـ API ثم الخروج |

## 3. الواجهة المرئية خطوة بخطوة

1. **الرابط** — الموقع المراد زحفه.
2. **الوضع** — `audit` (موقعك)، `competitor` (منافس)، أو `compare` (عدّة مواقع).
3. **استراتيجية الاكتشاف** — كيف يكتشف الزحف الصفحات:
   - **homepage** — يبدأ من الصفحة الرئيسية ويتبع الروابط (بحث بالعرض).
   - **sitemap** — يزحف الروابط المعلَنة في خريطة الموقع.
   - **hybrid** (الافتراضي) — الرئيسية والروابط أولاً، ثم روابط sitemap كبذور مؤجّلة.
4. **الحدود والسرعة** — أقصى عدد صفحات (0 = بلا حد)، أقصى عمق، وشريط سرعة (لطيف → أقصى).
   هناك حدّ أدنى من جهة الخادم لحماية المواقع.
5. **ما الذي يُجمَع** — مربّعات مجمّعة (الميتا، العناوين، الروابط، الصور، canonical، hreflang،
   ترقيم الصفحات، Open Graph، Schema.org، ترويسات HTTP، المحتوى المختلط، جرد الموارد).
   فعّل ما تحتاجه فقط لزحفٍ أسرع.
6. **صيغ المخرجات** — HTML, PDF, Excel, CSV, JSON, XML.
7. **نوع التقرير** — خبير (تقني كامل)، عميل (مختصر مبسّط مع درجة صحّة)، أو كلاهما.
8. **الإعدادات المتقدمة** (قابلة للطيّ) — التكاملات، مستشار الذكاء الاصطناعي، الاستخراج
   المخصّص، عتبات التحليل، و«فحص حالة HTTP للموارد». ومن خيارات الزحف المتقدمة:
   **قالب منصّة التجارة** (زد/سلة/Shopify/WooCommerce)، **التحكّم التكيّفي بالسرعة**،
   و**توليد sitemap.xml**. ومن بطاقات التكامل: **فحص الفهرسة (URL Inspection)** في GSC،
   و**اتجاه Core Web Vitals (CrUX History)** في PageSpeed — كلها تُضبط من الواجهة دون طرفية.

أثناء الزحف تعرض صفحة المهمة المرحلة الحالية، عدّاد وقت، عدّادات الصفحات، وزر **إيقاف**.
الإيقاف يُصدّر النتائج الجزئية أيضاً لتتمكّن من تنزيلها.

## 4. أوضاع الزحف

- **audit** — تدقيق SEO كامل لموقع واحد (الافتراضي).
- **competitor** — زحف منافس لبيانات المقارنة.
- **compare** — زحف عدّة مواقع (`sites_to_compare` في الإعداد) وإنتاج ملخّص مقارنة؛ كل موقع
  يحصل أيضاً على مجلده الخاص و`metrics.json` خاص به.

## 5. الملفات الناتجة

في الواجهة، كل شيء داخل `webapp_jobs/<job_id>/output/`. في سطر الأوامر، داخل مجلد المخرجات
المُعدّ.

- **`report_<site>_<ts>.html` / `.pdf`** — التقرير المنسّق (PDF يحتاج Playwright). في وضع
  «كلاهما» تحصل على `..._client.*` و`..._expert.*`.
- **`audit_<site>_<ts>.xlsx`** — Excel متعدد الأوراق (مناسب لتسليم العميل).
- **`audit_<site>_<ts>.json`** — أرشيف التدقيق الكامل (كل مجموعات البيانات).
- **`csv/`** — ملف لكل مجموعة: `pages`، `inlinks`، `outlinks_external`، `all_links`،
  `images`، `headings`، `schema`، `redirects` (+ `redirect_chains/loops/issues`)، `headers`،
  `seo_issues`، `duplicates`، `orphans`، `thin_content`، `pages_4xx/5xx/404_with_inlinks`،
  `images_no_alt/no_dimensions` (كاملة وغير مقصوصة)، `url_issues`، `canonical_issues`،
  `security_issues`، `pagination` / `pagination_issues`، `hreflang_issues`، `resources`
  (+ `resource_issues`، `resource_status`)، `custom_extraction`، `excluded_urls`،
  `gsc_pages/gsc_queries`، `ga4_landing_pages/ga4_channels`، `priority_opportunities`،
  `ai_recommendations`، `lighthouse_import`، `js_diff`، وعند تفعيل التكاملات أيضاً:
  `pagespeed_audits` / `pagespeed_network_requests` / `pagespeed_js_treemap` /
  `pagespeed_failed_audits` (جداول Lighthouse العميقة)، `keyword_cannibalization`،
  `internal_link_opportunities`، `gsc_index_status` (URL Inspection)، `crux_history`.
- **`sitemap.xml`** — يُولَّد من الصفحات القابلة للفهرسة عند تفعيل `output.generate_sitemap`.
- **`metrics.json`** — عدّادات وتوقيتات وملخّص «أبطأ المراحل».

**كيف تُنظَّم المخرجات (ولماذا تبقى بحجم معقول):**
- **`csv/` هو موطن البيانات الكاملة** — ملفات كثيرة صغيرة، كل ملف مختصّ بشيء واحد وباسم
  معبّر. هنا تعيش البيانات الكاملة، بما فيها شبكة الروابط (`all_links.csv`) وهي أكبر ملف
  طبيعياً على المواقع الكبيرة.
- **Excel** مصنّف عميل محدود (الأوراق مقصوصة عند 50,000 صف) — تسليم قابل للقراءة لا تفريغ خام.
- **JSON** يحتفظ بالصفحات + التحليلات + الملخّصات، ولا يُضمّن المصفوفات الخام الضخمة
  (روابط/صور/عناوين) افتراضياً (`output.json_full: true` لتضمينها).
- **XML مطفأ افتراضياً** — يكرّر بيانات CSV فقط. فعّله فقط إن احتاجته أداة أخرى؛ وهو مقصوص
  بـ`output.xml_max_rows`.
- للمواقع الضخمة جداً ضع **حدّ صفحات** لإبقاء الحجم صغيراً. الإعدادات أعلاه **لا تفقد أي
  معلومة** — كل شيء موجود في ملفات CSV.

**تنزيل المخرجات:** تعرض صفحة المهمة كل ملف ناتج مجمّعاً حسب النوع (تقارير، Excel، أرشيف،
بيانات CSV، XML) باسم واضح وحجمه. يمكنك تنزيل أي ملف منفرداً، أو **تنزيل الكل كملف ZIP واحد**
(«تنزيل الكل»)، أو تحديد مجموعة ثم «تنزيل المختار (ZIP)».

**استكشاف النتائج** (`/jobs/<id>/explore`) يتيح تصفية/فرز/بحث الصفحات في المتصفح وتنزيل
المجموعة المصفّاة كـ CSV. و**لوحة العمل** (`/jobs/<id>/board`) تعرض أولويات الإصلاح مجمّعةً
(افعل الآن / يحتاج مطوّراً / …) قابلةً للتصفية حسب المجموعة/نوع الصفحة/الأولوية. **اضغط أي صف**
لتفتح لوحة تفاصيل جانبية تجمع كل بيانات الرابط (الزحف + GSC + URL Inspection + GA4 + PageSpeed +
الأولوية + الوصولية) في مكان واحد. ومن صفحة المهمة يوجد رابطان آخران:
**🆚 مقارنة قبل/بعد** (`/jobs/<id>/compare`) لاختيار مهمّة أخرى ورؤية المُصلَح/الجديد/الباقي،
و**📜 تحليل اللوغ** (`/logs`) لرفع ملف سجلّ خادم Apache/Nginx وعرض ميزانية زحف Googlebot
لكل رابط (200/3xx/404/5xx) — كل ذلك محلياً بلا رفع خارجي.

## 6. التقارير: عميل مقابل خبير

اختر عبر **نوع التقرير** (أو `report.audience` في الإعداد):

- **خبير** — الوثيقة التقنية الكاملة: ملخّص تنفيذي، أولويات الإصلاح، كل المشاكل حسب الخطورة
  (مع عيّنات روابط)، الصفحات بمشاكل، الظهور البحثي (GSC)، سلوك المستخدم (GA4)، التحويلات،
  ترقيم الصفحات، hreflang، جرد الموارد، و Schema.org.
- **عميل** — ملخّص قصير غير تقني: **درجة/تقييم صحّة عام**، ملخّص تنفيذي بلغة واضحة، أهم
  الفرص، وأبرز المشاكل — بلا جداول تقنية عميقة.
- **كلاهما** — يُنتج ملفّين منفصلين؛ صفحة المهمة تعرض أزرار تنزيل منفصلة.

يمكنك أيضاً إعادة بناء التقرير بعد الزحف من صفحة المهمة (تغيير اللغة، اسم العميل، النوع،
وتوليد PDF من عدمه).

## 7. التكاملات (كلها اختيارية ومطفأة افتراضياً)

فعّلها من **الإعدادات المتقدمة ← التكاملات**. المفاتيح/المسارات تُحفظ في إعداد المهمة المحلي
فقط ولا تُكتب في المستودع. المفاتيح السرية تُمرَّر للعملية عبر متغيّرات بيئة لا على القرص.

| التكامل | ما يضيفه | ما تُقدّمه |
|---------|----------|-----------|
| **Google Search Console** | نقرات/ظهور/CTR/ترتيب لكل صفحة واستعلام + تحليلات تكلّس الكلمات وفُرَص الروابط الداخلية | ملف اعتماد OAuth + رابط موقع موثّق |
| **GSC — URL Inspection** (اختياري) | حالة الفهرسة الحقيقية لكل رابط (`gsc.url_inspection`) — يحترم الحصّة عبر `inspect_max_urls` | نفس اعتماد GSC |
| **Google Analytics 4** | جلسات/مستخدمون/تفاعل لصفحات الهبوط + القنوات | JSON لحساب خدمة + property ID (يحتاج `google-analytics-data`) |
| **PageSpeed API** | درجات أداء/SEO + **جداول Lighthouse العميقة** (تدقيقات/طلبات شبكة/خريطة JS/فاشلة) | مفتاح API (أو `PAGESPEED_API_KEY` في `.env`) |
| **CrUX History** (اختياري) | اتجاه Core Web Vitals عبر الزمن (`pagespeed.crux_history`) | نفس مفتاح PageSpeed |
| **استيراد Lighthouse** | يقرأ ملفات Lighthouse JSON محلياً (بلا مفاتيح/إنترنت) | مجلد ملفات Lighthouse `.json` |
| **Ahrefs Webmaster (AWT)** | استيراد تصديرات AWT بصيغة CSV (باك‑لينك/كلمات مجاناً لمالك الموقع) | مجلد ملفات CSV |

عند تفعيل GSC/GA4 يربط **التقرير الموحّد** المشاكل التقنية بحركة المرور لإنتاج **أولويات
الإصلاح** (`درجة الأولوية = أثر الزيارات × شدّة المشكلة`). كما تحمل كل مشكلة في التقرير حقول
**الأثر/الجهد/«لماذا تهم»/«كيف تُصلَح»/درجة الأولوية** لجعلها قابلة للتنفيذ.

### خيارات تشغيل إضافية (في `config.yaml`)
- **`site.platform_preset`** (`zid` | `salla` | `shopify` | `woocommerce`): يضيف أنماط استبعاد
  موصى بها (السلّة/الدفع/الحساب) دون مسح ما تضعه أنت.
- **`crawl.adaptive_throttle.enabled`**: تحكّم تكيّفي بالسرعة — يبطئ تلقائياً عند 429/5xx/البطء
  ويتعافى (احترام الخادم وتفادي الحظر).
- **`output.generate_sitemap`**: توليد `sitemap.xml` نظيف من الصفحات القابلة للفهرسة.
- **`pagespeed.save_raw_json`**: حفظ تقرير Lighthouse الخام الكامل لكل صفحة (مصدر الجداول العميقة).

### تسهيلات ربط Google
- **قوائم منسدلة بعد الربط:** زر «📋 جلب مواقعي من GSC» وزر «📋 جلب خصائص GA4» يملآن قائمتين
  منسدلتين تختار منهما الموقع/الخاصية مباشرةً (يجلبهما من حسابك بعد الموافقة، عبر Analytics
  Admin API لخصائص GA4).
- **«لصق الرمز» للأجهزة بلا متصفّح/الخوادم البعيدة:** بدل فتح المتصفّح محلياً، اضغط «احصل على
  رابط الموافقة»، افتحه في أي متصفّح، ثم ألصق الرابط الناتج (أو الرمز فقط).
- **قطع الربط كاملاً:** زرّ «🚪 قطع الربط» يحذف الـtokens؛ ولتغيير ملف client_secret استخدم
  زر القطع مع `?full=1` (أو احذف الملف من الواجهة بعد التحديث القادم).
- **دليل إعداد OAuth client لأوّل مرّة** متاح كقسم قابل للطيّ داخل الواجهة (3 خطوات + روابط
  مباشرة + ملاحظات حول وضع Testing وموافقة كل 7 أيام).

> **ملاحظة مهمّة عن «استهلاك حساباتك»:** قراءة بيانات GSC/GA4 لا تستهلك حصّة المشغّل — الحصّة
> لكل موقع/خاصية يملكها المستخدم نفسه. الشيء الوحيد المشترك هو مفتاح PageSpeed (لذلك بلا
> مفتاح افتراضياً). كل مستخدم/وكالة باستخدامه عميل Desktop OAuth خاصاً به يحقّق العزل الكامل.

### استخدام ملف `.env` للأسرار (مُوصى به)

أنشئ ملف `.env` في جذر المشروع:

```
PAGESPEED_API_KEY=your_key
GA4_PROPERTY_ID=123456789
GA4_CREDENTIALS_FILE=./secrets/ga4.json
AI_API_KEY=your_ai_key
```

يجب أن يكون `.env` ضمن gitignore. تقرأ الأداة هذه القيم كاحتياط.

## 8. مستشار الذكاء الاصطناعي (اختياري)

يقرأ المستشار ملخّص التدقيق + أهم الفرص ويُرجع ملخّصاً تنفيذياً وتوصيات محدّدة ومرتّبة
بالأولوية. **مطفأ افتراضياً**.

فعّله من **الإعدادات المتقدمة ← مستشار الذكاء الاصطناعي**:

1. **المزوّد** — OpenAI (GPT)، Google Gemini، DeepSeek، OpenRouter، Hugging Face، أو نقطة
   **متوافقة مع OpenAI** مخصّصة (للنماذج المحلية مثل Ollama / LM Studio).
2. **مفتاح API** — يُلصق في الواجهة (يُمرَّر عبر متغيّر البيئة `AI_API_KEY`؛ لا يُكتب على
   القرص أو في المستودع) أو ضع `AI_API_KEY` في `.env`.
3. **النموذج / عنوان الخدمة** — اختياري؛ اتركه فارغاً للافتراضي. `base_url` مطلوب فقط للنقطة
   المخصّصة.
4. **السماح بنقطة محلية/خاصة** — اتركه **مطفأً** للمزوّدات السحابية. فعّله **فقط** لنموذج محلي
   موثوق (مثل `http://127.0.0.1:11434/v1`)؛ وإلا تُرفض العناوين الداخلية/loopback كحماية SSRF.

الخصوصية: **لا تُرسَل بيانات شخصية (PII)** — فقط روابط الصفحات وأنواع المشاكل وأرقام مجمّعة.
تظهر النتيجة كقسم AI في التقرير وكملف `ai_recommendations.csv`. إذا غاب المفتاح/المكتبة أو فشل
الاتصال، يكتمل الزحف بشكل طبيعي.

## 9. قراءة اللوغ والتشخيص

- تعرض الواجهة التقدّم الحيّ؛ للتفاصيل افتح `webapp_jobs/<id>/run.log` (نظيف — بلا ضجيج أشرطة
  التقدّم) أو `webapp_jobs/<id>/logs/`.
- ملخّص نهاية الزحف يسرد الصفحات، الفاشلة، توزيع رموز الحالة لكل صفحة، الروابط، الصور، والحجم.
- **أخطاء الجلب المؤقتة** (شبكة/مهلة أُعيدت المحاولة لها) تظهر كسطر WARNING بعددها، وتُحصى أيضاً
  في `metrics.json` (`crawler.fetch.errors`).
- **الروابط الخارجية**: الملخّص يفصل `OK / محجوبة (401/403/429) / معطوبة`. المحجوبة هي حجب
  من السيرفر (بوت/معدّل طلبات) لا أعطال حقيقية.
- لوحة التشخيص في صفحة المهمة تلخّص الأخطاء/التحذيرات/التتبّعات من اللوغ.

## 11. استكشاف الأخطاء

- **0 صفحات / الكل فاشل** — راجع `run.log`؛ غالباً مشكلة شبكة/DNS أو ترميز، أو أن رابط البداية
  رُفض بحماية SSRF (استخدم رابطاً عاماً، أو فعّل `crawl.allow_private_hosts` لموقع داخلي).
- **PDF لا يُولَّد** — نفّذ `playwright install chromium`.
- **GA4 لا يعمل** — `pip install google-analytics-data` ثم قدّم property ID وملف حساب خدمة صحيح.
- **زرّ «اختبار اتصال» GSC/GA4 يقول «لم يُكمَل التفويض»** — أكمل **«وافق بحسابي»** (زرّ الربط)
  أولاً. اختبارات الاتصال **لا تفتح متصفّح موافقة** عمداً (كي لا يتعلّق الطلب)؛ الموافقة تتم
  مرّة واحدة عبر زرّ الربط فقط. الاختبارات أيضاً محدودة بمهلة فتُرجع رسالة «انتهت المهلة» بدل
  التعلّق إن تعذّر الاتصال.
- **الذكاء الاصطناعي «غير متاح»** — مفتاح API مفقود، أو `base_url` داخلي مرفوض (فعّل «السماح
  بنقطة محلية/خاصة» فقط للنماذج المحلية الموثوقة).
- **زحف بطيء** — قلّل عدد الصفحات أو ارفع شريط السرعة (قد يكون الموقع نفسه بطيئاً)؛ استخدم
  `--skip-external` لتخطّي فحص الروابط الخارجية.
- **الإيقاف لم يُظهر تنزيلات** — تأكّد أنك على الإصدار الحالي (يعالج إشارة الإيقاف في Windows
  ويُصدّر النتائج الجزئية).
- **زحف ضخم/غير محدود (ملفات بالغيغابايت أو تعليق عند فتح النتائج)** — على المواقع الكبيرة
  جداً تجنّب «كل الصفحات» (0) أو راقب الحجم. افتراضياً لا يُضمّن `complete_audit.json` المصفوفات
  الخام الضخمة (روابط/صور/عناوين) — موجودة في CSV/Excel — لتبقى النتائج خفيفة وسريعة الفتح.
  لأرشيف كامل فعّل `output.json_full: true` (قد يكون بحجم غيغابايتات). صفحات «استكشاف النتائج»
  وإعادة بناء التقرير ترفض ملفات JSON الأضخم من ~300MB وتوجّهك لملفات CSV.

## 12. الأمان والخصوصية

- يعمل محلياً بالكامل؛ لا يُرفع شيء إلا إذا فعّلت تكاملاً أو مستشار الذكاء الاصطناعي.
- حماية SSRF تمنع الزحف/التحويل إلى عناوين داخلية/loopback/ميتاداتا (تجاوزها لكل تشغيل عبر
  `crawl.allow_private_hosts`).
- تصديرات CSV/Excel تُحيّد حقن الصيغ (formula injection) للفتح الآمن في برامج الجداول.
- المفاتيح السرية في `.env` / إعداد المهمة المحلي (ضمن gitignore) وتُمرَّر للعملية عبر متغيّرات
  بيئة — لا تُرفع إلى Git.
- لا تُجمَع بيانات شخصية من GA4 ولا تُرسَل لمزوّد الذكاء الاصطناعي.


## الزحف على مرحلتين والروابط المؤجَّلة (v1.08)

على المواقع الكبيرة، كثير من الروابط المكتشفة لا تضيف قيمة SEO حقيقيّة لكنّها
تستهلك وقت الزحف: تركيبات ترقيم الصفحات العميقة، شاشات تسجيل الدخول المُلتَفّة
حول رابط الوجهة، وتركيبات الفلاتر المتعدّدة. مثال واقعي: زحف انتهى إلى **14,553**
رابط من نوع `/auth/login?redirect_to=...` لمنتجات الموقع — نسخة من شاشة تسجيل
الدخول لكل منتج، بلا محتوى مختلف يُفهرس. لو دخلت كلّها الطابور لاستغرق الزحف
ساعات إضافيّة دون مشكلة قابلة للإصلاح في التقرير.

لذلك يعمل SCT على **مرحلتين**:

- **Phase 1 — الزحف الأساسي:** يُفحَص ما يُكتشف من sitemap وقائمة التنقّل
  والروابط العاديّة. الأنماط المعروفة بإهدار الوقت تُصنَّف وتُحفَظ جانباً مع
  عدّاد لكل نوع — **لا تُحذَف ولا تُخفى عنك**.
- **Phase 2 — فحص المؤجَّلة (اختياري، يُشغَّل يدوياً بعد Phase 1):** يأخذ
  الروابط المؤجَّلة ويُدخلها الطابور في زحفٍ ثانٍ. لا يبدأ تلقائياً — أنت تقرّر
  بعد رؤية الأعداد هل يستحقّ.

### اللوحة الكهرمانيّة في صفحة المهمّة

عند انتهاء Phase 1 وإن وُجدت روابط مؤجَّلة، تظهر لوحة كهرمانيّة في **النتائج
والتقارير** بعنوان **🔍 روابط مكتشفة لم تُفحَص في Phase 1**. تعرض:

- **بطاقة لكل نوع** بعدّاده وتلميح موجز:
  - **📄 ترقيم عميق** (`pagination_deep`) — `?page=N` حيث N أكبر من
    `pagination_max`. الصفحات الأعمق عادةً نفس القالب بمحتوى متشابه، فالقيمة
    الإضافيّة من فحصها صغيرة مقابل تكلفتها.
  - **🚪 شاشات تسجيل** (`redirect_wrapper`) — مسارات مثل `/auth/login`
    أو `/login` مع معامل `redirect_to=`/`next=`/`return_to=`. هي شاشة واحدة
    تتكرّر بعدد المنتجات/الصفحات، وكثير من جدران الحماية (Cloudflare) تحجبها أصلاً.
  - **🧪 تركيبيّات فلاتر** (`filter_combination`) — تركيبيّات متعدّدة من
    `?filter[]=...` تتجاوز `filter_max`. عدد التركيبات ينفجر أُسّياً (3 فلاتر
    × 4 خيارات = عشرات الآلاف)، والصفحة الناتجة غالباً غير قابلة للفهرسة.
  - **❓ أخرى** (`other`) — لم تطابق أيّ نمط معروف.
- **زرّ Phase 2** — يبدأ زحفاً ثانياً يضخّ المؤجَّلة في الطابور. أثناء عمله،
  العدّادات في الأعلى تتقدّم كما في أي زحف عادي، ويمكنك إيقافه في أي لحظة.
- **زرّ تنزيل قائمة المؤجَّلة (CSV)** — يفتح `csv/deferred_urls.csv` مباشرةً
  دون تشغيل Phase 2، لتفحصها بنفسك أو تفتحها في Excel.
- **زرّ عرض أمثلة لكل نوع** — يطوي/يبسط قائمة عيّنات (حتّى 10 روابط لكل نوع)
  لتعرف عيناً ما الذي أُجِّل وتؤكّد أنّ التصنيف صحيح.

### متى تُشغّل Phase 2، ومتى تتخطّاه

| الحالة | القرار المقترح |
|--------|-----------------|
| العدّاد بالآلاف ومعظمه `redirect_wrapper` أو `filter_combination` | **تخطَّه** — هذه الأنماط نادراً ما تُفهرَس، وفحصها يضيف ساعات بلا مكسب SEO. |
| العدّاد صغير (مئات) أو فيه `other` بحجم ملحوظ | **شغّله** — قد يكشف صفحات حقيقيّة لا تظهر في sitemap. |
| موقع تجارة بحجم متوسط مع `pagination_deep` كبير | **افحص العيّنات أولاً** — إن كانت صفحات تصنيف فعليّة (لا تكرار) فشغّله؛ إن كانت ترقيماً بلا قيمة فاكتفِ بـPhase 1. |
| تدقيق تشخيصي شامل (مرّة كلّ ربع، مثلاً) | **شغّله** — تريد صورة كاملة حتّى لو طال الوقت. |
| تدقيق دوري متكرّر | **تخطَّه** — اكتفِ بـPhase 1 لتسريع التكرار. |

### مكان الملفّات

- **`output/csv/deferred_urls.csv`** — قائمة كاملة بالروابط المؤجَّلة وأسبابها
  (الرابط + النوع). يظهر مع باقي ملفّات CSV في «كل الملفّات الناتجة» وفي
  «تنزيل الكل (ZIP)».
- لا يُولَّد الملف إن لم يُؤجَّل أي رابط — مثل بقية الملفّات الشرطيّة.

### ضبط حساسيّة المُصنِّف

نوعا التأجيل الرئيسيّان قابلان للضبط — كلاهما برقم بسيط:

| المفتاح | الافتراضي | المعنى |
|---------|-----------|--------|
| `pagination_max` | `3` | أعمق صفحة ترقيم تُفحَص في Phase 1. `?page=4` فأعلى يُؤجَّل. `0` = بلا حدّ (فحص الكلّ، يعطّل تأجيل الترقيم). |
| `filter_max` | `1` | أقصى عدد فلاتر متزامنة. تركيبة بفلترين تظلّ في Phase 1، بثلاثة فأكثر تُؤجَّل. `0` = يعطّل تأجيل الفلاتر. |

ارفع `pagination_max` على مدوّنة طويلة تستحقّ صفحاتها العميقة الفهرسة، واخفضه
على متجر تجاري ضخم. ارفع `filter_max` فقط إن كنت تعلم أن تركيبات الفلاتر لديك
canonical-ed بشكل صحيح؛ غير ذلك أبقِه عند الافتراضي.
